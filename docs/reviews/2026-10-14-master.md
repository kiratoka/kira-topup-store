## Masalah Minor

### 🟡 Spread parameter `extra` pada `apiError` dapat menimpa kunci reserved, `lib/errors.ts:18`
**Masalah**: Parameter `extra` di-spread paling akhir di objek respons, yang berarti pemanggil yang meneruskan `{ success: true }` atau `{ message: "..." }` sebagai `extra` akan menimpa field kanonikal `success: false` dan `message` secara diam-diam.
**Mengapa ini penting**: Meskipun `extra` saat ini hanya diteruskan oleh kode internal (bukan input eksternal), hal ini merupakan footgun potensial bagi developer di masa mendatang. Kesalahan seperti `apiError('Error', 400, undefined, { success: true })` akan menghasilkan respons 400 yang kontradiktif dengan `success: true`.
**Saran perbaikan**: Antara melakukan spread `extra` sebelum kunci-kunci reserved (sehingga `success` dan `message` selalu menang), atau menambahkan runtime guard yang menghapus kunci-kunci reserved dari `extra` sebelum digabungkan. Sebagai alternatif, dokumentasikan kontrak tersebut dalam JSDoc.

### 🟡 `NEXT_PUBLIC_BASE_URL` digunakan pada callback Midtrans namun tidak divalidasi oleh env guard, `app/api/payment/route.ts:115`
**Masalah**: Objek `callbacks` pada rute pembayaran menggunakan `process.env.NEXT_PUBLIC_BASE_URL` untuk menyusun URL pengalihan finish, error, dan pending. Variabel ini tidak disertakan dalam skema `lib/env.ts` (yang memvalidasi lima variabel sesuai AC-5).
**Mengapa ini penting**: Jika variabel ini tidak disetel pada saat deployment, URL callback Midtrans akan menjadi `undefined/invoice/ORDER-xxx`, yang secara diam-diam merusak pengalihan setelah pembayaran selesai. Hal ini sudah ada sebelum perubahan saat ini dan berada di luar cakupan spesifikasi, namun kehadiran env guard merupakan peluang bagus untuk menangkapnya.
**Saran perbaikan**: Pertimbangkan untuk menambahkan `NEXT_PUBLIC_BASE_URL` ke dalam skema env pada tindak lanjut berikutnya, atau minimal tambahkan fallback saat runtime disertai log peringatan.

### 🟡 Fallback dead code `|| ''` pada variabel env yang kini sudah dijamin oleh env guard, `app/api/payment/route.ts:17` dan `app/api/payment/notification/route.ts:45`
**Masalah**: Beberapa tempat masih menggunakan `process.env.MIDTRANS_SERVER_KEY || ''` meskipun env guard kini telah memastikan variabel-variabel tersebut ada dan tidak kosong sejak startup. Fallback tersebut tidak akan pernah dieksekusi.
**Mengapa ini penting**: Dead code menimbulkan kebingungan bagi pembaca kode di masa mendatang yang mungkin bertanya-tanya apakah env guard dapat dipercaya. Hal ini bertentangan dengan tujuan dari guard yang bersifat fail-fast.
**Saran perbaikan**: Ganti `process.env.MIDTRANS_SERVER_KEY || ''` dengan `process.env.MIDTRANS_SERVER_KEY!` (non-null assertion, aman karena adanya guard) atau import `env` dari `lib/env.ts` dan gunakan `env.MIDTRANS_SERVER_KEY` secara langsung. Terapkan secara konsisten di seluruh rute payment dan notification.

## Catatan Kecil (Nits)

- ⚪ `app/api/invoice/[orderId]/route.ts:13`: Guard `!orderId` merupakan dead code pada Next.js App Router, yang selalu menyediakan string tidak kosong untuk segmen dinamis. Tidak berbahaya namun membingungkan.
- ⚪ `app/api/payment/notification/route.ts:45` vs `:87`: Pola akses tidak konsisten untuk `MIDTRANS_SERVER_KEY` dalam file yang sama. Baris 45 menggunakan fallback `|| ''`, baris 87 mengaksesnya langsung tanpa fallback. Pilih salah satu pola.

## Kelebihan

- Cakupan pengujian menyeluruh: setiap jalur error secara eksplisit memverifikasi bahwa `data.error`, `data.stack`, dan `data.cause` bernilai undefined, memastikan tidak ada regresi kebocoran data. Pengujian verifikasi rantai impor AC-7 (membaca file sumber untuk memeriksa `import '@/lib/env'`) merupakan pengujian struktural yang kreatif dan efektif.
- Desain helper `apiError` yang bersih: ukuran kode minimalis (< 20 baris), urutan spread yang benar untuk `code`, dan mudah diadopsi. Migrasi diterapkan secara konsisten di semua rute.
- Perbaikan bonus: memperbaiki hardcoded `isProduction: false` menjadi `process.env.MIDTRANS_IS_PRODUCTION === 'true'` pada konstruktor klien Snap di rute pembayaran, memperbaiki bug produksi yang nyata saat melakukan perubahan di area tersebut.
- Semua pesan kesalahan konsisten dalam Bahasa Indonesia tanpa mengekspos data internal teknis.
